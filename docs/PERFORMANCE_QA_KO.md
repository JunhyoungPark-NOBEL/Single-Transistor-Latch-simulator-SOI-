# 성능 탭·실행 전 시간 예측 확인

2026-09-26

## 변경 범위

성능 탭, 모델·해석별 실측 표, 연결된 Python 계산 환경의 측정, 현재 실행 요청의 예상 시간 표시를 추가했다. 소자 및 자유 배치 회로의 실행 버튼에 같은 예측 체계를 적용한다. Geometry, Simple의 기하 의존 확산 β, 바디 재결합 등 소자의 물리식은 변경하지 않았다.

이전 배포본과 비교한 기존 Python 파일의 변경은 계산 종류 등록, 작업 실행시간 기록, API·요청 정규화와 관련 검사에 한정된다. 원본 소스 ZIP의 `engine/` 66개 파일은 바이트 단위로 일치한다.

## 실제 측정

기준 표는 43개 모델·조건 항목으로 구성된다. 이 중 실측은 34개, 미지원은 9개다. 실측 34개에는 예측 기준에서 제외한 추가 확인용 CSVM 4개 항목이 포함된다. 모델 쌍은 같은 외부 입력·수치 허용오차를 사용하지만 파형과 적응 스텝 수는 다를 수 있다.

| 대표 조건 | Detailed 중앙값 | Simple 중앙값 | 비율 |
|---|---:|---:|---:|
| ID–VD · 601점 | 0.1930 s | 0.0325 s | 5.95× |
| CSVM · 1 pF · 15 ms | 0.9635 s | 0.1030 s | 9.36× |
| CSVM · 1 fF · 40 µs | 0.2808 s | 0.1191 s | 2.36× |
| CSVM 회로 · STL 4개 | 3.6811 s | 0.3345 s | 11.00× |
| 5단자 CSVM · Body RC | 0.8596 s | 0.2343 s | 3.67× |

공유 AMD EPYC 9V74 환경, Linux x86_64, Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0, Numba 0.67.0에서 측정했다. 노출 논리 CPU는 9개, CPU quota는 8개이며 수치 라이브러리의 스레드 제한은 1개다. 위 표는 준비 후 5회 계산의 중앙값이며 API 결과 캐시를 사용하지 않았다.

기존 Numba 디스크 캐시는 유지했다. 최초 호출 열은 완전히 새로 설치한 PC의 JIT 준비 시간이 아니다. 확률적 일반 모델의 기본 격자는 이 배치의 첫 계산에 약 15.87 s, 계산표 재사용 후 100회 계산에 약 0.0699 s가 걸렸다. 따라서 반복 계산의 짧은 시간을 새로운 조건의 최초 실행시간으로 표시하지 않는다.

전체 표·조건·반복 횟수·원자료·재현 명령은 [벤치마크 기록](benchmarks/performance/README-KO.md)에 있다. 모든 측정 과도 해석이 요청한 종료 시각에 도달했는지 확인했다.

## 예측 확인

기준 표에 포함하지 않은 20 µs CSVM을 Detailed / Simple 각각 2회 실행했다. `dt_max`를 고정한 채 기간만 절반으로 바꾸면 예측 오차가 약 1.2% / 2.9%, UI처럼 기간과 `dt_max`를 함께 절반으로 바꾸면 약 28.0% / 37.1%였다. 네 조건은 모두 0.5–2배 범위 안에 들었다. 이는 작은 조건 집합의 확인이며 임의 회로에 대한 정확도 보증은 아니다.

실행 전 숫자는 추정 범위다. 적응 스텝, Newton 수렴, 새로운 바이어스·Geometry와 동시 사용량의 영향을 완전히 예측하지 못한다. 최초 준비·미확정 대기는 별도 표시하며 네트워크 전송과 화면 렌더링은 제외한다.

**이 환경 측정**은 실제 계산 worker에서 Detailed / Simple의 ID–VD 및 CSVM, 총 4개 조건을 실행한다. 보정은 같은 모델·해석 종류에만 적용한다. 그 외 종류는 해당 호스트에서 정상 완료한 실행 기록이 생기기 전까지 기준 환경 추정으로 표시한다. 기준 벤치마크 표와 현재 호스트의 측정 기록은 구분한다.

## 소프트웨어 확인

|---|---|
| API·작업 관리자·인증·성능 통합 검사 | 187개 통과, 비관련 장시간 항목 4개 제외 |
| 독립 성능 구조 검사 | 16개 통과 |
| 벤치마크 입력·작업량 검사 | 5개 통과 |
| 전체 프런트엔드 단위 검사 | 41개 파일, 573개 통과 |
| TypeScript·배포용 화면 빌드 | 통과 |
| 실제 Python API에 연결한 Chromium 검사 | 2개 통과, 수치 응답 모의 처리 없음 |
| 화면 확인 | 데스크톱·390px 모바일, 가로 넘침·브라우저 실행 오류 없음 |
| Linux 실행 준비 검사 | Python 의존성·배포 화면·API import 준비 확인 |
| 원본 엔진 및 설치 파일 | 엔진 66개 원본 일치, 포함 CPython 설치 파일 SHA-256 유지 |

검사 범위는 겹칠 수 있으므로 행별 숫자를 합산하지 않는다. 백엔드는 실제 환경 측정 2회가 캐시를 사용하지 않는지, 새 Simple 계산이 기록되고 같은 결과의 캐시 응답은 추가 표본이 되지 않는지 확인했다. 취소·실패·미완료·최초 준비 시간을 warm 학습에서 제외하며, 여러 사용자의 공유 실행은 한 번만 기록한다.

API 추정은 수치 엔진을 import하거나 실행하지 않는다. 비밀번호 보호, 잘못된 요청, 결과 캐시의 대기열 우회, 공유 작업·병렬 작업·의존 관계, 다른 서버의 지연 응답 폐기를 확인했다. 보정 기록은 호스트·엔진·Python 수치 환경·추정 코드별로 구분하고 30일 후 만료한다.

실제 브라우저에서는 4개 조건의 환경 측정, Simple CSVM의 기간 15 → 7.5 ms 변경에 따른 요청·예측 갱신, 실행 전 숫자 표시, 실제 계산 완료 후 캐시 표시 전환, 자유 배치 회로의 실제 netlist를 이용한 예측을 확인했다. 캡처와 API 응답 기록은 `web/review/performance/`에 있다.

Windows 자동 설치 구성과 연구실 서버 설치 구성을 포함한다. 이번 환경에서 Windows 네이티브 설치나 연구실의 실제 서버 배포를 수행한 것은 아니다. 이 변경에서 전체 물리 회귀 검사를 다시 실행하지 않았으며, 성능 비교를 물리 정확도의 검증으로 해석하지 않는다.
