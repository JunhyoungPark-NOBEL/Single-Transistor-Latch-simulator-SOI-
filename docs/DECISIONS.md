# Implementation decisions (append-only)

- [foundation] Engine copied verbatim from the handoff zip into `engine/`; runtime caches are gitignored.
- [foundation] `server/params.py` reads every calibrated number from the engine JSON files (single source of truth); `build_p()` reproduces `setup_photo.BASE` exactly for the paper preset and `S.params(...)` for the photo preset (checked to 1e-27).
- [foundation] Photo preset applies the body-coupling option γ = 0.2794 (p[15]) as `mc_cycles.py` does; the high-V_D seed (p[17], p[18]) stays an alternative option in the UI (open problem).
- [stochastic] Hazard curves generalise `photo_fpt.hazard_curve` to the full 26-element p (same voltages/u grid/lattice; classify grid = device.numerics.grid, default 601); window 0.28 V is extended to 0.5/0.8 V only when the escape probability in the window's first 10 mV exceeds 1e-3 at the requested rate (gate_fpt uses 0.5 V near V_G = -1.1 V). Cross-check VG -2 V dark 0.4 V/s: 3.6442 V / 8.03 mV.
- [stochastic] Disk cache `server/.cache/stochastic/{fold,hazard}/<sha256>.json`, key = sha256(CACHE_VERSION, p formatted '%.12g', algorithm settings); one file per fold node / hazard node so sweep_mc, hazard and vg_curve_stochastic share work; atomic writes (tmp + os.replace) for concurrent workers.
- [stochastic] State mapping (general engine): gidl X = extra dg on p[9] (centre 0, build_p already holds δφ_G0); local_avalanche X = p[23] (centre ext.dloc, p[21] forced to 1.0 with a warning when ext.aloc <= 0); junction X = p[19]; multiplication X = p[20]. cycle_state and fold_table.delta are X - centre; absolute centre in the extra key state_axis.
- [stochastic] Fold table: classify at X0 + σ·linspace(-4.5, 4.5, fold_nodes), PCHIP over nodes with a latch, evaluated through a 4001-point fine grid; states whose nearest node has no latch (or outside the valid node range) are 'no latch' -> that cycle is censored (mc_cycles.py clips instead; the fraction is reported as no_latch_weight + warning).
- [stochastic] Emitter state: linear fold shifts dV_LU/dE and dV_LD/dE from classify at E = ±σ_E around the centre state (both applied).
- [stochastic] Carrier noise: LU hazard nodes at Gauss-Hermite states X0 + σ t_k (hazard_nodes), log hazard tabulated on a 1 mV distance-to-fold grid, bilinear in (X, distance) in log space, clamped to the end nodes outside their range, held constant between the last computed voltage and the fold (as gate_state_lookup.npz), zero beyond the window. LD hazard only at the centre state vs distance above the LD fold.
- [stochastic] MC time stepping: triangular sweep, steps+1 points per half (dt = dv/rate), trapezoidal ∫h dt vs an Exp(1) threshold; the event voltage is linearly interpolated inside the step (continuous values, no 2 mV quantisation); fold crossing interpolated likewise. Random numbers: Z, U, Z_E, U_LD drawn up front from default_rng(seed) (Z, U in mc_cycles.py order = common random numbers); OU innovations from default_rng([seed, 11]) / ([seed, 12]), exact AR(1) discretisation, continuous across cycles and chunks.
- [stochastic] Latch-down is paired with latch-up: a cycle that never latched up (censored V_LU) has V_LD = null (gate_dynamic_compare treats up/down unpaired).
- [stochastic] Calibrated engine: V_LU/V_LD are gate_dynamic_compare's 10 mV read-out midpoints (VALIDATION numbers: 3.634 V/119 mV, 2.700 V/21.4 mV); continuous values in extra keys V_LU_continuous/V_LD_continuous. cycle_state comes from an exact replay of simulate()'s random stream (verified bit-identical events in the tests). auto also requires carrier_noise = true (the lookup always contains LU and LD first-passage noise).
- [stochastic] vg_curve_stochastic: fold table on the same nodes as sweep_mc (X0 + σ·linspace(-4.5,4.5,fold_nodes), cache-shared), PCHIP onto vg_sweep.py's 81-point grid t ∈ [-4, 4] with Gaussian weights; FPT noise SD and mean shift from photo_fpt.quantiles at hazard_nodes GH states, added in quadrature; evolving states use their stationary distribution; σ_E ignored (moves V_LD); latch window by bisection (2.5 mV) of the centre-state latch existence (extra key `window`).
- [physics-B] Topics stochastic-events, first-passage, local-states, sweep-mc, circuit-element, design-map, open-problems, validation live in `web/src/content/physics/topics/<id>.ts`; shared helper `topics/_sharedB.ts` has no default export, so the registry glob ignores it. Every equation carries a `code` reference; numbers quoted were re-run (FPT node 3.6442 V / 8.03 mV, dynamic MC 3.6344 V / 119.0 mV, 2.6999 V / 21.4 mV, 10×100 pooled 125.8 / 19.6 mV with seeds 2026093000+k, fold sensitivities −0.796 and −39.8 V/V).
- [physics-B] design-map relations are *inferred* from the arrays (generator not in the handoff) and labelled so in the UI; each matches to machine precision: N̄ = N_t·L0², σ_φ = (1−d)·q·√N_t / (2·C'_ox·L0) with C'_ox = 3.9ε0/EOT, σ_VLU and latched_fraction = PCHIP of data/fill_response_sweep4V.json (latched = switched/1000), φ_50mV = PCHIP root at 50 mV, iso-lines at d = 0. sigma_VLU_sweep5p2V_mV is shown as given.
- [physics-B] Inconsistencies documented in the content (code untouched): photo_mean p[24] = 2 ("edge without channel") is unreachable because `bulk = p[24] > 0.5` is tested first (p[24] = 2 ≡ 1, verified); stl_api.py smoke text says FPT SD "6.8 mV" (code 8.03, VALIDATION ≈ 8) and photo V_LD "2.5959" (code 2.5962); dV_LD/dφ_E is −39.8 V/V for the fold and −41.2 V/V for the lookup escape mean; MODEL_SPEC §1 / data/tables `Q_B` is the excess charge only, not the lattice/circuit coordinate C_ox ψ + Q_exc + qN_A A L_n.
- [physics-B] Cross-package observations (for the owners, not changed): validation.py `check_paper_records` uses seeds 2026092920+k (gives 119.6 / 18.9 mV) although gate_dynamic_compare.main() uses 2026093000+k (reproduces 125.8 / 19.6 mV exactly); the general sweep engine with `ld_carrier_noise: false` (preset default) puts V_LD at the fold (2.599 V vs 2.7007 V with it on, measured 2.7001 V).
- [physics-A] Topics overview, electrostatics, impact-ionization, btbt-gidl, channel, bjt-transport, charge-balance, photo, parameters, numerics are written as plain `PhysicsTopic` objects (one file each, TeX in `String.raw` literals where possible, no shared helper file). Every quoted number was recomputed against the engine (`stl_api`, grid 601) on 2026-09-24.
- [physics-A] Code finding (engine left untouched): in `photo_mean.components()` `bulk = p[24] > 0.5` is also true for p[24] = 2, so the "edge excluding channel" local-path definition (`edge_only`) is unreachable; p[24] = 2 gives outputs identical to p[24] = 1 (verified). Documented in impact-ionization/parameters; UI/backends should not present 2 as a distinct option without a wrapper fix.
- [physics-A] Three charge definitions coexist and are documented as such in charge-balance: z[13] = C_ox·u + Q_exc (components), Q_B = Q_exc (export_tables / MODEL_SPEC §1, §5), Q = C_ox·ψ + Q_exc + q·N_A·A·L_n (compound_fpt lattice, WEB_CONTRACT circuit element). The quasi-potential U(x) is described exactly as WEB_CONTRACT §2 states it (backend-defined).
- [physics-A] MODEL_SPEC vs code differences recorded in the topics: V_D relation omits R_c (code uses (R_c + R_acc)·I_D); photo-electrons are multiplied by max(M−1,0) without the channel-II scale p[12] (spec says "like channel electrons"); I_PH enters the transport solver only via the collector-side boundary source b, not as distributed generation.
- [stochastic] Local caps mirror server/payloads.py (defensive for direct calls) except dv_V >= 0.5 mV (MC cost; clamped with a warning); calibrated_lookup requested explicitly for a non-reference device / action / vd_max != 4 raises ValueError instead of silently switching engines. Node cache dir overridable with env STL_STOCH_CACHE_DIR.
- [backend-core] Jobs run in a `spawn` ProcessPoolExecutor; progress and cancel flags travel through two `multiprocessing.Manager` dicts; the worker-side progress callback writes at most every 0.2 s and raises `JobCancelled` when flagged. DELETE reports `cancelled` immediately (the worker stops at its next progress call; a result that still completes is cached but not attached).
- [backend-core] Results are serialised to JSON bytes inside the worker (orjson, NaN/inf → null) and embedded with `orjson.Fragment`; endpoints return explicit Response objects (FastAPI's `jsonable_encoder` is bypassed).
- [backend-core] Cache key = sha256(kind, canonical JSON of the *normalised* payload (sorted keys, ints as floats), clamp warnings, ENGINE_VERSION); ENGINE_VERSION also hashes `server/engine_bridge.py`. Identical in-flight payloads are de-duplicated to the running job.
- [backend-core] The API process normalises payloads before submission (`server/payloads.py`): device/sweep/stochastic blocks are resolved from the preset, caps clamped with warnings (prepended to `result.warnings`), structural errors → 422. `vg_curve_stochastic` keeps the stochastic package's own vg_min/vg_max/n defaults.
- [backend-core] Extra internal kind `folds` (`deterministic.run_folds`, folds only) backs the `/api/folds` alias; it is listed in `/api/meta` as `extra_kinds`, not in `kinds`.
- [backend-core] `charge_balance`: `S.state` raises when the r bracket [0, vd−u] ends where `components()` is NaN (depletion edge past the neutral-length limit, e.g. V_D = 5 V, u ≥ 0.91 V); `deterministic.state_row` then shrinks the bracket to the finite part with identical row formulas. The u grid adds 40 log-spaced points on [1e-9, 0.02] V because the low-V_D HRS root sits at u ≈ 1e-7 V.
- [backend-core] `double_sweep` inserts each fold jump as two points at the same V_D (fold current, then the other branch); ≤ 2001 grid points per direction.
- [backend-core] Latch-window edges = latch-existence limits of `classify()` (grid 601) by bisection to 1 mV: −3.906 / −0.810 V vs the paper's −3.90 / −0.815 V (within 10 mV).
- [backend-core] Validation "carrier noise only" breakdown is derived, not copied: compound FPT lattice with one channel class as jumps (II clusters | unit generation GIDL+BTBT_j | REC bulk+junction SRH | DIFF) and the rest as deterministic drift, upwind on a lattice refined N = 4, 8 + Richardson in log h → II 5.1, BTBT 3.0, REC 4.2, DIFF 1.9, all 8.0 mV (paper 4.6/2.7/4.3/1.8/7.8); tolerance ±1 mV. The FPT-node SD check uses VALIDATION.md's ≈ 8 mV (stl_api.py's comment says 6.8 mV; the engine gives 8.03 mV).
- [backend-core] Default worker count is container-aware (affinity + cgroup cpu.max); Docker image runs as uid 1000 with /app writable (numba caches, photo_nodes, server/.cache) and `scripts/warmup.py` at build time.
- [orchestrator] Presets now enable `ld_carrier_noise` by default: without the latch-down FPT the general engine places V_LD exactly at the fold (2.598 V for the paper device vs 2.700 V measured); with it 2.6996 V.
- [orchestrator] Engine finding (physics-A): `photo_mean.components` tests `bulk = p[24] > 0.5`, so p[24] = 2 ("edge excl. channel") is unreachable and equals p[24] = 1. Engine kept verbatim; UI offers 0/1 only.
