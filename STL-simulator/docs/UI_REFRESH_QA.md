# STL simulator UI refresh verification

On 2026-09-25, the production build passed and all **3 targeted Chromium gates passed in 12.2 seconds**. The gates are in `web/e2e/stl-ui.spec.ts`. Separately, the complete frontend test suite passed **536 tests across 36 files**.

## What was checked

| Area | Verified behavior |
| --- | --- |
| Name and modes | Browser title and brand say `STL simulator`. The controls say `결정론적` and `확률적`, remain visible on narrow screens, and support arrow-key selection. |
| Device structure | FDSOI is selected; PDSOI and Bulk are disabled. No alternative physical model is implied by choosing a disabled technology. |
| Geometry schematic | All six dimension/body targets select and focus their corresponding input by mouse and Enter. Selection alone leaves numerical values unchanged. L changes persist after the store's normal 250 ms save debounce. |
| Typography | Geometry variables and KPI main symbols are italic; descriptive subscripts are upright. Actual Plotly axis labels use the same convention. |
| Readability | Geometry input text is at least 14 px on desktop and phone, navigation tabs at least 14 px, mode controls at least 13 px, and computed chart tick text at least 12 px. Current chart defaults are 13 px. |
| Themes | Light/dark mode changes update the actual chart palette, with readable geometry labels and controls. |
| Responsive layout | No horizontal page overflow at 1440, 390, or 320 px. At 390 px, the brand and menu do not overlap; the geometry drawer and schematic can be used. |
| VSCM | The real HTTP API supplies the reference ID–VD curve and the UI displays VLU 3.704 V and VLD 2.598 V. |
| CSVM | The real HTTP API supplies the transient, displaying Vtop 3.742 V, Vbottom 2.586 V, and frequency 860 Hz. |

The production frontend was served by FastAPI, not the development mock mode. The final VSCM and CSVM responses came from the API's cache of previously computed numerical results; they were not intercepted or generated by browser fixtures. This refresh rechecks presentation and API integration, not the numerical solver's physical accuracy. Earlier independent solver and authenticated remote-server checks are documented in `STUDIO_QA.md` and `RELEASE_CHECKS_KO.md`.

The review corrected the top-view W selection hit area and a CSS font shorthand that reset KPI italics. The final checks wait for persisted state and return to the page top before capture. No UI defect was hidden by replacing numerical data.

## Reproduction

From `web/`, build the frontend:

```sh
npm run build
```

From the repository root, start the actual API with the built frontend:

```sh
STL_WORKERS=2 python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
```

Then from `web/`:

```sh
E2E_PORT=8000 STUDIO_LIVE=1 npx playwright test e2e/stl-ui.spec.ts
```

Playwright reuses the server at that port. Without `STUDIO_LIVE=1`, these live API gates are explicitly skipped. In an execution environment with per-command network isolation, start the API and Playwright as child processes of the same parent command. Stop the API after verification.

## Limits

The geometry drawing is explanatory and is not a dimensionally scaled device reconstruction or an automatic full-depletion test. This UI refresh adds no physical effects, does not calibrate additional geometries, and does not validate PDSOI or Bulk support. The current browser verification used Chromium on Linux; it does not validate a native Windows installation or deployment on a particular laboratory server.
