STL simulator / Setup

내 PC에서 시작하고,
연구실 서버로 연결하세요.

화면은 그대로 두고 계산할 위치만 바꿀 수 있습니다. 연구실 서버 주소를 직접 열면 설치 없이 같은 앱을 사용할 수 있습니다.

01   로컬 실행

받은 압축파일을 전부 풀어 실행하세요. Windows 10/11 x64에서는 Python이 없으면 자동 설치합니다. macOS/Linux는 Python 3.11 이상을 먼저 설치합니다.

Windowsstart-local.bat 더블클릭
macOS · Linux터미널에서 sh start-local.sh

첫 실행은 Python 확인·준비 후 필요한 패키지를 설치합니다. 패키지를 받기 위해 인터넷이 필요합니다. 준비되면 브라우저가 자동으로 열립니다. 계산 중 터미널을 유지하고, 종료할 때 Ctrl+C를 누르세요.

Windows 설치 · 오류 기록

패키지에 포함된 공식 Python 설치 파일을 사용하며, 기존 Python을 사용할 수 있으면 재설치하지 않습니다. 설치 상태는 studio-startup.log에 남고, 실패하면 메모장으로 열립니다. 자동 설치는 현재 사용자용으로 구성되어 있습니다.

start-local.bat --check
start-local.bat --port 8100
포트 변경 · 실행 확인
python launch.py --check
python launch.py --port 8100
python launch.py --no-browser

화면 파일이 포함되어 있으므로 실행만 할 때 Node.js는 필요하지 않습니다. 설치에는 최초 한 번 인터넷 연결이 필요합니다.

02   연구실 서버 연결

  1. 화면 위 연결에서 연구실 서버를 선택합니다.
  2. 서버 주소를 입력합니다. 예: https://lab.example.edu
  3. 필요하면 서버 비밀번호를 입력하고 연결 확인을 누릅니다.

주소 끝에 /api는 붙이지 않습니다. URL만 기억하며, 비밀번호와 세션 토큰은 저장하지 않습니다. 새로고침 후에는 다시 로그인합니다.

연결이 안 될 때

관리자가 서버의 STL_CORS_ORIGINS에 현재 화면의 주소를 허용해야 합니다. localhost와 127.0.0.1, 서로 다른 포트는 각각 등록합니다. HTTPS 화면에서는 HTTPS 서버를 사용합니다.

STL_CORS_ORIGINS=http://127.0.0.1:8000,http://localhost:8000

로컬 서버로 돌아가려면 연결 창에서 로컬을 선택하세요. 저장한 소자는 현재 브라우저에 남아 있습니다.

03   서버 관리자

배포 패키지의 STUDIO_START_KO.md에 전체 설치 순서가 있습니다. compose.yml과 deploy/에는 Docker·nginx·systemd 설정이 포함되어 있습니다.

기본 구성 보기

환경 파일을 /etc/biristor-studio/server.env에 두고 비밀번호와 세션 키를 설정합니다. 컨테이너는 기본적으로 서버 내부의 8000 포트에만 열리며 HTTPS 프록시로 연결합니다.

docker compose up -d --build
docker compose logs -f --tail 80 studio

API 서버 하나가 별도의 계산 프로세스 2개를 관리합니다. STL_WORKERS로 계산 작업 수를 조절하고 uvicorn의 --workers는 추가하지 않습니다.
